# Playwright Visual Regression Testing Framework

A GitHub-ready TypeScript framework for visual regression testing with Playwright Test, screenshot
assertions, snapshot baselines, responsive checks, masked dynamic content, and CI quality gates.

## Purpose

Visual regression testing catches unintended UI changes by comparing current screenshots with
approved baseline screenshots. This project uses a deterministic local demo website so tests do not
depend on public websites, remote images, live APIs, or random data.

## Features

- Full-page, component, responsive, dark-mode, masked-content, and interaction-state comparisons.
- Playwright screenshot assertions with expected, actual, and diff artifacts.
- Stable screenshot preparation for fonts, animations, transitions, caret blinking, and dynamic text.
- Separate projects and snapshot paths for desktop and mobile visual baselines.
- Smoke tests on Chromium, Firefox, and WebKit.
- HTML reporting, trace/video retention on failure, ESLint, Prettier, strict TypeScript, and GitHub Actions.

## Technology Stack

TypeScript, Playwright Test, Playwright screenshot assertions, dotenv, ESLint flat config, Prettier,
http-server, rimraf, npm, and GitHub Actions.

## Architecture

- `config/`: environment, viewport, and visual assertion defaults.
- `fixtures/`: custom Playwright fixtures for visual tests.
- `pages/`: page object methods and reusable locators.
- `utils/`: visual stability helpers, snapshot naming, comparator wrapper, and logging.
- `test-site/`: deterministic local HTML/CSS/JS demo application.
- `tests/visual/`: screenshot comparison suites.
- `tests/smoke/`: functional smoke tests without screenshot assertions.
- `docs/`: visual strategy and baseline management guidance.

## Prerequisites

- Node.js 20.11 or newer.
- npm.
- Playwright-supported browser dependencies.
- Docker is optional for CI-compatible baseline generation.

## Installation

```bash
npm install
npx playwright install
```

## Running Tests

```bash
npm test
npm run test:visual
npm run test:visual:chromium
npm run test:visual:mobile
npm run test:smoke
npm run test:headed
npm run test:ui
npm run test:debug
npm run ci
```

Playwright starts the local demo site automatically at `http://127.0.0.1:4173` through `webServer`.

## Snapshot Management

Generate initial baselines explicitly:

```bash
npm run snapshots:update
```

Update only Chromium desktop baselines:

```bash
npm run snapshots:update:chromium
```

Normal test commands and CI do not update snapshots. Snapshot updates must be reviewed and approved.
Updating snapshots is not a method for hiding unexpected visual defects.

## Visual Coverage

- Full-page comparison: home, product, and dashboard pages.
- Component comparison: header, hero, feature card, product card, statistic card, and navigation.
- Responsive comparison: desktop, tablet, and mobile viewports from `config/viewports.ts`.
- Dark-mode comparison: separate light and dark baselines.
- Dynamic-content masking: dashboard timestamp and status regions.
- Interaction-state comparison: modal, cart notification, selected tab, and mobile menu.

## Snapshot Naming and Storage

Snapshots are organized by test file, Playwright project, and snapshot name:

```text
tests/__screenshots__/<test-file>/<project-name>/<snapshot-name>.png
```

Expected snapshot PNG files are intentionally not ignored by Git and should be committed after
approval.

## Visual Artifacts

- Expected screenshot: the approved committed baseline.
- Actual screenshot: the screenshot captured during the failing run.
- Difference screenshot: the pixel-difference image generated by Playwright.

Open the HTML report with:

```bash
npm run report
```

The report is generated in `playwright-report`. Failure artifacts are generated in `test-results`.

## CI/CD Quality Gate

GitHub Actions runs on pushes to `main`, pull requests targeting `main`, and manual dispatch. CI uses
`npm ci`, installs Playwright browsers, checks formatting, runs TypeScript, runs ESLint, runs smoke
tests, and runs the primary Chromium visual quality gate. CI never updates snapshots.

## Cross-Platform Screenshot Differences

Screenshots can vary by operating system, browser build, font rendering, and device scale factor.
This framework minimizes drift with fixed Playwright projects, deterministic local assets, stable
locale/timezone, disabled animations, CSS-scale screenshots, and separate baselines by project.

Preferred official baseline strategy:

```bash
npm run docker:update-snapshots
npm run docker:test
```

The Docker image in `Dockerfile` matches `@playwright/test` version `1.59.1`.

## Environment Variables

Copy `.env.example` to `.env` for local overrides when needed:

```text
BASE_URL=http://127.0.0.1:4173
VISUAL_MAX_DIFF_PIXEL_RATIO=0.001
VISUAL_THRESHOLD=0.2
VISUAL_FAIL_ON_DIFFERENCE=true
```

Do not commit `.env`.

## Troubleshooting

- Missing baselines: run `npm run snapshots:update`, review PNG files, and commit approved expected images.
- Unexpected visual diffs: open `npm run report`, inspect expected, actual, and diff screenshots, then fix the UI or approve the change.
- Local and CI differ: regenerate official baselines in Docker or the same Linux CI environment.
- Flaky screenshots: check animations, fonts, dynamic regions, viewport sizes, and external dependencies.

## Limitations

The sample application is intentionally local and deterministic. Cross-browser visual baselines are
not shared; Chromium is the primary visual gate, while Firefox and WebKit run smoke checks.
